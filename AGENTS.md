# The Plan — agent working rules

The product is a premium made-for-you scrapbook invitation. Gift pages, the internal Studio, production dashboard, customer form, and the storefront payment-to-form bridge are implemented. Treat deployment as a separate, explicitly authorized operation.

Read `PRD.md`, `src/project.ts`, and `README.md` before changing code. Keep copy and media in project data, not hardcoded in rendering components. Preserve Indonesian and English UI copy parity. Validate data at boundaries. Keep sections modular and avoid large all-purpose files when expanding the product.

Keep all palette definitions in `src/themes.ts`. Keep the shared song catalog in `src/music-playlist.json`; Studio and the customer form must read the same catalog. Gallery editing exposes captions only and uses each caption as accessible image text. Text presets must never overwrite factual event details, customer media, or the rundown. Store only a supported theme ID on the project; never duplicate raw palette colors inside orders, drafts, or gifts. The recipient gift must not expose a theme switch. Theme choice belongs in the customer form and internal Studio.

The Studio's QR stamp must encode the public `/gift/{projectId}` link and use the last published project's palette. Keep a four-module quiet zone around the QR matrix and verify PNG decoding when changing its SVG geometry. Draft palette edits do not recolor an already published barcode until republish.

For customer orders, obtain the real KV project ID and order ID first. Read `order:{orderId}` and its submitted `answers` before producing any copy or selecting media. The customer form has no email or WhatsApp fields. Its UI display language is independent from `answers.contentLanguage`, which is `id`, `id-en`, or `en`. The single `story.message` is the Letter source; `story.letterMode` decides whether the team may expand it (`expand`) or must keep the customer's wording (`keep`); and `story.tone` is an array of selected writing styles. Check optional `answers.deadline` before scheduling work. Use only customer-uploaded R2 URLs from `answers.media` and `answers.music.uploaded`, plus explicit customer facts for date, time, venue, Maps, photos, and music choice. When `answers.music.mode` is `upload`, verify the audio file, title, artist, and cover before publication. Do not invent missing factual details. Form submission pre-fills `draft:{projectId}` with all directly mappable content while preserving raw answers in the order. Treat that draft as a starting point: inspect the raw order before polishing it, honor `letterMode` and all selected tones, and never silently discard uploaded gallery media. `POST /api/internal/orders/:orderId/apply` is an explicit restore operation: it reapplies the form-owned fields and may overwrite Studio polishing, so use it before polishing or only when an intentional reset is requested. Store polished editable content at `draft:{projectId}` and only approved published data at `gift:{projectId}`. A draft edit must never change a published gift until the owner publishes it. The dashboard reuses Studio's signed internal session and reads `order:`, `draft:`, `gift:`, and `response:` records through protected Worker endpoints.

Project identity changes must go through `PUT /api/internal/projects/:projectId/identity`; never rename individual KV keys by hand. The route migrates all linked project records and updates the order. A custom hostname must first be attached to the Vercel frontend, then stored through the same route so `domain:{hostname}` maps its root to one published gift. Never expose a form token, Studio session, internal URL, or `project-meta` record from a public endpoint. Use the shared review template when sending a published link through WhatsApp so the copy remains consistent between Studio and dashboard.

Form links are private capabilities. Never print, log, or expose `formToken` outside the authenticated Dashboard and the customer URL. Public form endpoints must validate `X-Form-Token`; public responses must never return the token. Preserve raw submitted answers for audit even when polishing the draft.

Manual payment and webhook payment must converge on the same form → incoming order → agent application → owner review → publish workflow. Keep raw customer answers intact for audit, and write polished gift content into the draft. Do not claim Stage 1 local RSVP storage is production persistence.

Run `npm run check` for code changes. Inspect mobile and desktop rendering and the exported 1080×1920 PNG when gift rendering changes. Never push or deploy without the owner's current instruction.
